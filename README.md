# typeshit — рукописный генератор

Самодостаточный аналог texttoimages.pro: превращает текст в фотографически правдоподобные
страницы рукописных работ. Ключевое отличие — **почерк снимается с реального человека**:
пользователь печатает шаблон, пишет в клетках буквы, фотографирует лист, сервер вырезает
каждую букву в отдельный спрайт (со всеми повторами) и измеряет наклон, разброс и нажим.
Дальше текст пересобирается из этих спрайтов с вариативностью, помарками и «видом снято
на телефон».

Один бинарник на Go, без GPU, без внешних сервисов, без CGO. Данные — обычные файлы.

```
┌──────────────┐   шаблон A4   ┌───────────────┐   профиль JSON + атласы PNG
│  браузер     │ ────────────► │  Go-сервер    │ ─────────────────────────────┐
│  (web UI)    │ ◄──────────── │  net/http     │                              │
└──────────────┘   страницы    └───────────────┘                              │
        ▲                             │   layout → ink → paper → effects      │
        │                             ▼                                       │
   REST /api/v1                 PNG · JPEG · PDF · ZIP ◄──────────────────────┘
```

## Быстрый старт

```bash
go build -o typeshit ./cmd/server
./typeshit -addr 127.0.0.1:8080 -data ./data
# открыть http://127.0.0.1:8080
```

```bash
# мгновенный демо-почерк из встроенного шрифта (без фотографии)
curl -s -X POST localhost:8080/api/v1/profiles \
  -H 'content-type: application/json' \
  -d '{"name":"Демо","fontId":"badscript","variants":3,"lang":"ru"}'

# отрендерить страницу
curl -s -X POST localhost:8080/api/v1/generate \
  -H 'content-type: application/json' -d @request.json
# -> {"id":"r...","pages":["/api/v1/results/r.../page-001.png"],"millis":1200}
```

## Свой почерк (главный сценарий)

1. **Шаблон** — `GET /api/v1/template?lang=ru&reps=2` отдаёт 2–3 страницы A4 @300dpi с
   клетками, бледными образцами букв, пунктирной базовой линией и чёрными L-метками по углам.
2. **Письмо** — пользователь пишет по одной букве в клетку. `reps` = число повторов, каждый
   повтор становится отдельным вариантом глифа. Чем больше повторов, тем живее почерк.
3. **Съёмка** — фото сверху, без вспышки. Сервер: даунскейл → выравнивание освещённости →
   адаптивный порог → поиск угла поворота по проекции → перспектива по L-меткам →
   гомография в канонический A4 → привязка сетки → базовая линия каждой строки.
4. **Разметка** — в браузере: рамки ячеек, назначение буквы кликом/клавишей, перенос,
   масштаб, добавление и удаление ячеек, отчёт о нехватке символов. Можно несколько листов
   сразу — они соберутся в один профиль.
5. **Профиль** — спрайты упаковываются в атласы, из данных измеряются `StyleModel`
   (наклон, σ поворота/масштаба/базовой линии/межбуквенного, σ чернил, доля соединений).

## Что умеет рендер

| Слой | Возможности |
|---|---|
| Бумага | тетрадь в линейку, клетка, точки, чистый лист; цвет, шаг клетки, поля, старение (желтизна, лисьи пятна, потёртые углы, кофейный круг) |
| Ручка | шариковая (сухие пропуски), гелевая, карандаш (зерно), перьевая (мокрый ореол, сгущение на поворотах), давление, растекание, цвет |
| Почерк | выбор варианта глифа без повторов подряд, поворот/масштаб/наклон/сдвиг базовой линии, дрейф по строке и по странице, псевдо-связки между буквами (кубические кривые по точкам входа/выхода) |
| Ошибки | зачёркивание, исправление над строкой с кареткой, переписывание буквы, пропуск слова с вставкой, подчёркивание, заметки на полях, кляксы, размазня, пятна, заломы |
| Съёмка | телефон (наклон, перспектива, тень, виньетка, неравный свет, JPEG-артефакты), скан, факс |
| Вывод | PNG (страницы), PDF (по странице на лист), ZIP |

Всё детерминировано по `seed`: одинаковый запрос → одинаковые байты.

## Внешний каталог шрифтов (отладка паритета)

Кроме встроенных девяти шрифтов сервер умеет подхватывать каталог с диска —
шрифты показываются в «Браузере шрифтов» на странице генератора (живое превью,
поиск, категории и фильтр кириллицы) и в `GET /api/v1/fonts`, из любого можно
собрать профиль через `POST /api/v1/profiles {"fontId": ...}`.

```bash
python3 scripts/fetch-parity-fonts.py --dir data/fonts   # 112 шрифтов + catalog.json
./typeshit -data ./data                                 # по умолчанию читает <data>/fonts
./typeshit -data ./data -fonts /path/to/fonts           # или явный каталог
```

Каталог читается один раз при старте: `*.ttf` / `*.otf` + необязательный
`catalog.json` (`{"fonts":[{"id","name","category","scripts","languages"}]}`).
Файлы без записи в каталоге получают имя файла как название. `data/` в
`.gitignore`, так что выкачанные шрифты в репозиторий не попадают — это
чужие начертания, только для локального сравнения.

## API для агента

Полная спецификация: `GET /api/v1/openapi.json`.

```
GET    /api/v1/health
GET    /api/v1/fonts                        GET /api/v1/fonts/{id}/file
GET    /api/v1/profiles                     POST /api/v1/profiles {name,fontId,variants,lang}
GET    /api/v1/profiles/{id}                DELETE /api/v1/profiles/{id}
GET    /api/v1/profiles/{id}/preview?text=  GET /api/v1/profiles/{id}/atlas/{file}
GET    /api/v1/template?lang=ru&reps=2      GET /api/v1/template/{lang}/{reps}/{page}.png
POST   /api/v1/capture       (multipart: file + spec JSON)
GET    /api/v1/capture/{id}, /capture/{id}/image
POST   /api/v1/capture/{id}/cells   {cells:[{id,rect,label}]}
POST   /api/v1/capture/{id}/commit  {name, assignments:[{cellId,label}], mergeInto?}
POST   /api/v1/generate  {text, profileId, seed, page, paper, pen, style, effects, flaws}
GET    /api/v1/jobs/{id}
GET    /api/v1/results/{id}/page-001.png · export.pdf · export.zip
```

Асинхронный режим: добавьте `"async": true` (или `?async=1`) — вернётся `{"jobId": ...}`.

Минимальный запрос:

```json
{
  "text": "Конспект по истории.\n\nВ 1861 году отменили крепостное право.",
  "profileId": "p...",
  "seed": 42,
  "paper": {"kind": "lined", "cellMm": 9, "aging": 0.2},
  "pen": {"kind": "ballpoint", "color": "#1b2a55", "pressure": 0.6},
  "effects": {"kind": "phone"},
  "flaws": {"crossOut": 0.02, "correction": 0.03, "smudge": 0.25}
}
```

## Устройство

```
cmd/server            HTTP-сервер
internal/model        контракты (профиль, спрайт, страница, запрос)
internal/profile      съёмка почерка: шаблон, анализ скана, разметка, атласы, merge
internal/layout       текст → расстановка глифов, перенос, колонки, помарки
internal/ink          растеризация чернил (нажим, сухость, ореол, штрихи)
internal/paper        фон страницы и старение
internal/effects      имитация съёмки
internal/api          REST + отдача собранного web UI
internal/store        файловое хранилище (profiles/captures/results/jobs)
internal/webui/static HTML/CSS/JS без сборки
```

`docs/HANDWRITING.md` — геометрия спрайтов и пайплайн съёмки, `docs/CONTRACT.md` —
внутренний контракт пакетов.

## Производительность

A4 1240×1754: рендер ≈ 0,15–1,3 с/страница (12 потоков не нужны, хватает одного ядра),
фон ≈ 0,1 с, «телефон» ≈ 0,5 с, анализ скана 2480×3508 ≈ 2 с. Бинарник ~12 МБ, RAM < 300 МБ.
